# Classic compatibility gaps

This register tracks the work needed to run compiled Classic scenarios as
Remake campaigns. It is intentionally separate from opcode coverage: an opcode
may already have interpreter semantics while still waiting for a native Remake
bridge, and an unsupported opcode may map cleanly to an existing Remake system.

## Classification

Priority describes the effect on a scenario rather than the size of the work:

- **Required**: missing behavior can block progression, change authored state or
  outcomes, or prevent a scenario from being installed, played, or saved.
- **Recommended**: the current fallback preserves progression and the authored
  result, but presentation, pacing, or interaction differs from Classic.

Implementation status describes the Remake side of the gap:

- **Implemented**: the completion criterion has focused integration coverage.
- **Native, unwired**: Remake has a suitable system, but the Classic adapter does
  not yet call it.
- **Partial**: some variants work, while others still stop or use a fallback.
- **Absent**: Remake has no corresponding system yet.
- **Resource gap**: the runtime path exists, but converted data or Remake
  resources do not preserve what it needs.
- **Unknown**: the closest native behavior or the Classic contract still needs
  source and fixture research.

Evidence is recorded as **fixture-proven**, **source-backed**, **inferred**, or
**unknown**. A row moves to completed only after its completion criterion is
covered by a focused fixture or playtest.

Stable trigger IDs, chances, and random rectangles use Remake's existing map format, and the normal resource loader retains generated map metadata for campaign-start seeding. Undecoded custom atlases, special land tiles without suitable decoded media, incomplete tile arrays, and unsupported render modes stop installation instead of receiving a lossy fallback. The host reapplies persistent darkness, landlook, random-rectangle, moved/replaced Action Point, trigger-percent, and tile mutations after native resources load. | Battles and battle context | Partial | Source-backed | Basic, branching, and selective battle requests now resolve native `Battle_<id>` resources, preserve pre-battle presentation and loot modes, wait for normal Remake combat cleanup, and resume the Classic action list. The installer also materializes supported compiler-produced monster records through the normal campaign Bestiary lifecycle, preserving the complete source record, both Classic identities, core combat statistics, size, type tags, physical attacks, and a deterministic reward estimate. Shared icon art, averaged random statistics, and omitted Classic difficulty/reward rolls remain explicit fidelity fallbacks. Spell lists, inventory and weapon behavior, special attacks, run or surrender behavior, and distinct Charm/Mental save semantics block launch when referenced. Authored cowardice outcomes show Classic's core warnings and mapped sound, then remove 2,000 experience per character level once; Remake's inverse `exp_tnl` representation is handled explicitly. Successful land movement supplies the original entry delta so cowardice also returns the party to its previous tile; dungeon outcomes preserve Classic's no-retreat behavior, and triggers without movement context report the skipped retreat. Opcode `48` supplies only the picked living characters, prevents their defeat from becoming a whole-party game over, and preserves its survivor-dependent fixed treasure. Opcode `127` queries the native live roster by the preserved Classic monster name byte and stops its combat macro when the required monster is absent. Opcodes `121` and `125` remove eligible live combatants through the native roster, using Data MD record IDs and monster name bytes respectively, preserve Classic's undead-tier and faction rules, and register hostile removals with battle rewards. Opcode `123` filters its compiled monster record IDs to the macro actor's faction, applies Remake's permanent fleeing AI, and removes routed combatants through native cleanup when they reach the battlefield's outer inset. Classic's ally sentinel prevents the exit. Other routed hostiles remain reward-eligible; routed allies leave without entering rewards, and neither path fires a death macro. Opcode `124` resolves compiled monsters into native combatants, places them near the macro actor, adds them to the live roster and initiative, and preserves both Classic identity values plus count, capacity, sound, and faction rules. The native bridge invokes opcode `126` schedules at one-based round boundaries and supplies live battle-macro context. Deaths capture their macro, actor position, faction, and Classic identities before removal; the bridge drains that FIFO asynchronously before checking battle victory, including entries added by another death macro. Opcode `100` ends a live native battle as a forced victory, uses the normal cleanup flow with experience-only rewards, terminates its combat macro, and carries Classic's slot-8 sentinel back to the suspended outer action point so no later action runs. Opcodes `82` and `83` gate a once-per-character native Turn Undead action. Compiler metadata preserves the original target flags, hit dice, magic resistance, and summon sentinel; successful destruction uses normal death and reward handling, while turned targets join the player faction. | Authored battles respect priest-turning availability, execute combat action points and macros at native lifecycle boundaries, and resume suspended outer action lists after forced combat exits. |

These items can remain behind a compatibility fallback while required work is
in progress. A scenario-specific audit may promote one to Required when its
presentation contains information needed for progression.

| Timed tumbler lock interaction | Absent | Source-backed | The rogue resolver applies Remake stats and Classic modifiers directly, preserving success and failure results. | A native interaction reproduces the timed tumbler rules without changing the resolved encounter result. |
| Standalone Classic player maps | Partial | Fixture-proven | Immediate display requests use decoded runtime art, the compiled map name, and its note without requiring a native minimap. Maps/Notes browses acquired Classic records in stable ID order and keeps note-only records available when decoded art is missing. Native minimaps remain the fallback for campaigns without acquired Classic records. | Add terrain-composed and scrolling-text views plus embedded marker overlays. |
| Classic picture, sound, and UI pacing | Partial | Source-backed | Existing Remake controls and mapped sounds are used where possible. Picture actions preserve display and dismissal order when the converter supplies a decoded image. Combat spawning uses native placement without Classic's conjuration animation. | Scenario presentation follows the authored ordering, dismissal, timing, and media choices where they affect fidelity rather than progression. |

## City of Bywater opcode coverage

All 2,734 active action slots in the checked City of Bywater bundle now have
defined interpreter behavior. This does not close the integration and fidelity
gaps above, or prove paths outside the trigger-slot coverage report.
